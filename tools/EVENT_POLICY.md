# One event per card — t55u/t56u

A card must identify one concrete event/performance/edition, not a venue's monthly
repertoire, a roundup, “where to go”, or a carousel whose individual events have
not been extracted. A named festival, exhibition spanning dates or repeated
performances of one named show remain valid identities. Do not reject merely
because text contains “festival”, “programme” or several dates.

`event_policy.json` contains conservative RU/KK/EN heading patterns and explicit
IDs/URLs of nine reviewed bad cards. `event_policy.py` is shared by both IG
entry points, Telegram, cleanup and the native-data generator. Headings include
the card title and the first nonblank caption line. Pattern matching is not a
complete semantic event parser: uncertain content still needs editorial review.
Do not create fictional individual events from carousel images. A roundup with
real announcements can only be split later using independently verified facts.

IG scan ingestion also requires an extracted date, venue (not the account
handle) and concrete /p/ or /reel/ permalink. `approxDate` alone is not admission.
The legacy imginn snippet importer has no verified date/venue and now skips
these snippets rather than creating undated account-level cards. Telegram keeps
its stricter full-date/year/city/venue checks. No OCR, translation or guessed year.
Rejected imports are skipped/review-logged; raw scan histories remain untouched.

The first and repertoire cards are the two user reports; the others are confirmed
monthly schedules/carousel summaries or generic ticket promotions without an
identified show. No individual shows were invented from these posts. Specific
Wonderland/Multi Fest/Flavi Fest and named theatre/ballet cards remain.

`prune_invalid_events.py` applies the same policy idempotently to feed/assets and
canonical feed_data. These nine never existed in feed_data or generated native
FakeEvents/Descriptions, so those data blocks need no regeneration. `gen_feed.py`
filters canonical input before producing either platform's native fallbacks.
Raw IG scans and old reports may still quote the rejected posts; they are audit
history, not current feed. Reimport tests verify they cannot resurrect cards.

Android `EventContentPolicy.kt` is generated by `gen_event_policy.py` from the
same JSON. FeedRepository filters parsed assets/remote/disk, merged and in-memory
feeds and native fallback output. A subsequent load writes the cleaned merge to
the existing disk file; no preferences, valid cached cards or files are cleared.
Known IDs/URLs remain blocked even if their title changes. JSON null, empty and
literal null/None prices normalize to nullable absence, including cached/fallback
cards. No UI redesign.
